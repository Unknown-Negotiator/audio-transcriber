# Validation record — 20 October 2026

## What was tested

This is a local CPU transcription CLI, not a guarantee of verbatim or error-free speech recognition. All testing used assistant-created fixtures and publicly available recordings, never files from a user's computer. macOS tests ran on hosted Apple Silicon ARM64 and Intel x86_64 machines running macOS 15.7.9, not on a personal MacBook Air M1. No Apple GPU acceleration was tested or implemented.

## Accuracy against independently supplied reference transcripts

A separate fixed sample of 12 Russian and 12 French human-recorded Google FLEURS test clips was evaluated. The corpus supplies reference transcripts; they were not generated by Whisper. Each model was given the known language. These total only 121.68 seconds of Russian and 133.02 seconds of French, with 206 and 338 normalized reference words respectively. The sample was selected deterministically before inference.

| Platform | Model | Russian WER | French WER |
|---|---|---:|---:|
| Linux | small | 8.25% | 14.20% |
| Linux | medium | 3.88% | 7.99% |
| Linux | large-v3-turbo | 1.46% | 5.03% |
| macOS ARM64 | large-v3-turbo | 1.46% | 5.92% |
| macOS Intel | large-v3-turbo | 1.94% | 5.03% |

WER counts word substitutions, deletions and insertions relative to the reference. It is not a percentage of semantic correctness. Case and punctuation were normalized; accents were preserved. An independent jiwer implementation reproduced every reported per-clip and aggregate edit count. Cross-platform outputs were not identical despite matching weights and settings.

This small clean read-speech sample does not prove general model ranking, performance on unseen training data, accuracy throughout the long files, or performance on noisy meetings, overlapping speakers, technical names or code-switching. No comparable real-English reference benchmark or hour-long real-English test was run. English functionality was initially smoke-tested with short synthetic speech only.

## Final code and timestamp regression

Long-recording and paired-reference inference above used application SHA256 `d57234cdd27a55a79da2980e2a85e5797c9699d9bf2655f04b1868708de8eade`, preserved at `accuracy/app_snapshot/transcribe.py`.

Inspection found model-generated timestamps extending beyond the recording, and suspicious trailing text such as a subtitle credit. The final display-only patch bounds timestamps and progress to the decoded PCM duration and emits a warning containing the raw interval. It deliberately retains recognized text and leaves inference settings unchanged. **Clipping timestamps does not remove hallucinations or restore omitted speech.** Review warned segments against the audio.

The final application SHA256 is `532b240122f6a3e1f8d405391bf0a5e864bb9ce6398a968625777415ffad53dd`. Its separate [final macOS regression run](https://github.com/Unknown-Negotiator/audio-transcriber/actions/runs/39506793958) passed 13 regressions and actual two-minute Russian turbo inference on each architecture, including timestamp bounds and unchanged input. Retained results are in `validation/final-cli/`. Historical full-length and accuracy scores were not rerun under this formatting patch and must not be represented as such.

## Bugs corrected

- Decoder resampler is recreated when consecutive input segments change audio format/channel layout; a synthetic fixture tests this.
- Model downloader includes `preprocessor_config.json`, required for large-v3/turbo's 128 mel features. An actual failed run exposed the omission; it was corrected before successful turbo tests.
- Displayed timestamps/progress are bounded as described above. No generated text is silently deleted.

## Offline scope and storage

Transcription requires local model files and enables offline flags; model acquisition is a separate explicit setup command. During tested transcription, the harness blocked Python socket connections. This is **not** a native-code firewall or complete OS network audit. Disconnect networking after setup for stricter assurance. No audio is intentionally uploaded by the application.

Measured model directories: small 486,213,827 bytes, medium 1,530,573,193 bytes, turbo 1,621,667,653 bytes. Large-v3's approximately 3.09 GB is published size, not a downloaded/tested model here. Models are not bundled. The isolated Linux environment used about 745 MB of file content plus 345 MB of package-cache content; Mac sizes can differ.

Plan roughly 4–5 GB free for a turbo installation and working room, excluding large original recordings. This is a planning estimate, not a measured Mac installation total. Temporary mono 16 kHz PCM WAV costs about 115 MB/hour; decoded float32 audio about 230 MB/hour, plus model/features/runtime memory. Conda package caches can sit outside the environment unless configured otherwise. CPU int8 does not shrink the initial model download.

## Remaining limitations

No speaker diarization, no Apple GPU/Metal backend, no validation of noisy multi-speaker meetings, and no exhaustive test of every media codec or every hour-long file. Timestamps are approximate segment estimates, not word-level alignment. A completed file and timestamps reaching its end do not establish that every spoken word was captured. Important transcripts need human review.
